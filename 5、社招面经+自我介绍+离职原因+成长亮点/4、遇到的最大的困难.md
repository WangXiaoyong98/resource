# 你在从业经历中遇到的最大的难题是什么
    故事背景是这样的，我们这边给客户提供一款已经量产的MCU芯片，客户在烧录启动镜像文件时，发现部分开发板可以正常启动，部分开发板无法启动。客户把这个情况反馈给FAE，FAE在做了一些尝试之后，没能解决掉，就把问题反馈给我们这边研发，因为我是软件部门对外的接口人，这家客户在前期导入时候我记得芯片是可以正常 work 的，根据这个部分开发板不能正常启动的情况，我初步判断是 spi + flash 通信过程中出现了问题。
    因为我们芯片在量产和前期客户导入阶段都会对我们的硬件IP和软件驱动进行回归测试和压力测试，所以首先，我怀疑是 spi 和客户使用的 flash 颗粒的兼容性问题，是不是客户用了非我们推荐的flash 颗粒。于是，我这边向客户进行询问，在拿到客户使用的 flash 颗粒信息后，我这边就去测试了，发现客户使用的 flash 颗粒是通过我们兼容性测试的。
    然后我就怀疑是不是客户使用的flash颗粒质量问题，flash中的某些地址出现硬件故障，导致某些bit写不进去，这个时候我就请求客户向我们邮寄一块他们的开发板，在拿到客户的开发板后，我这边对客户的开发板进行了擦读写测试，发现其中确实是有些bit位出现数据错误，并且这个错误的数据位并不是固定的。因为错误位不固定，所以基本可以排除flash颗粒本身有固定坏快的可能（因为如果是固定坏快的话应该是导致特定bit永远无法翻转）
    这个时候，我判断，这个flash颗粒应该是好的，那出问题的就是这个通信链路上，首先，我怀疑是我 spi 时钟频率设置过高，导致在开发板上因走线差异导致时序余量不足，也就是我芯片 spi 做master 往 flash 里面写数据的时候，flash 没有写进去就马上传进来下一位的数据，为了验证我的猜想，我首先是查询了flash 的 spec ，然后拿示波器量了一下 spi 的clk 脚，发现频率是满足要求的，并且我把 spi controller 的时钟频率降下来发现故障现象依然存在，那就可以排除是 SPI 时钟频率过高的问题。
    接下来怀疑PCB设计问题。我使用逻辑分析仪同时抓取SPI四根信号线（CS、CLK、MOSI、MISO），在故障板子上捕获正常发送过程。

    发现：逻辑分析仪解码显示，我司芯片发出的数据完全正确，与预期写入数据一致。

    但这里有一个矛盾：发送的数据正确，读回的数据却错误。这意味着问题可能出在数据写入Flash的过程中，而不是SPI传输过程。
    既然逻辑分析仪抓到的数据是正确的，但Flash实际写入是错误的，我开始怀疑：MOSI引脚的实际电平，在Flash采样时刻是否真的达到了高电平阈值？这个猜测偏硬件了，也就是我spi的数据传输的工程中，会有较大的瞬态电流，导致电源电压下降，进而导致 spi 控制器在连续大批量数据传输时出现瞬时电压跌落，进而引发写入错误。
    软件这边的解决方案是 ： 在 flash 驱动层实现 分块写入 + 片选复位 + 主动延时机制，将单次连续传输限制在 4KB 以内，并为每次传输后提供 200us 的电源恢复窗口。后续在故障板上验证，支持最大 256KB 连续写入，成功率为 100%。
