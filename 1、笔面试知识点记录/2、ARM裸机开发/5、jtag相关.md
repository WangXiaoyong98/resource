JTAG 调试的核心原理，可以概括为：调试器通过 JTAG 接口，操纵芯片内部一个名为 TAP 控制器的“总开关”，来访问芯片内部集成的调试模块（如 ARM 的 Embedded ICE），从而实现对 CPU 的控制。 而“Halt 住 CPU”这个关键动作，本质上就是调试器写入了调试模块里的一个特定控制位。

1、halt 原理
    1.1 、TAP控制器（Test Access Port）： 是一个由 TCK、TMS、TDI、TDO 四个信号线控制的状态机，相当于是一个串行通信的总指挥，负责接受调试器发来的命令和数据，并路由到正确的内存寄存器
    1.2、 指令寄存器（IR）和数据寄存器（DR）： TAP 控制器访问的两类信合寄存器
            IR： 用来存放当前的JTAG指令
            DR： 用来存放当前的JTAG数据
    1.3 片上调试模块 (如 Embedded ICE)：这是实现 Halt 功能的关键。ARM 等处理器在内部集成了这个模块，它包含一些特殊的比较器和控制寄存器。调试器正是通过 JTAG 接口修改这个模块的寄存器，来设置断点或让 CPU 暂停

2、核心机制
    设置断点地址：调试器将你想暂停的代码地址，写入调试模块的 断点地址比较寄存器。

    使能断点：设置对应的控制寄存器，告诉调试模块“当 CPU 要取指这个地址时，就触发调试事件”。

    CPU 运行：调试器通过 JTAG 清除暂停状态，让 CPU 正常运行。

    触发断点：当 CPU 的取指单元准备去 fetch 这个地址的指令时，调试模块的比较器检测到了匹配。

    产生调试异常：调试模块会向 CPU 核心发出一个内部 暂停请求 (Halt Request)，其优先级通常高于普通中断。

    CPU 响应并暂停：CPU 在执行当前指令后，响应这个请求，保存当前状态，然后进入 调试状态 (Debug State)。

    通知调试器：CPU 进入调试状态后，通常会将内部一个状态位的变化通过 JTAG 接口（TDO 引脚）反馈给调试器，告知“我已经暂停了”。

    方式二：软件断点 (利用临时指令)
    这是一种备选方案，不需要硬件比较器。

    读取指令：调试器通过 JTAG 边界扫描链，读取你想设置断点位置处的原始指令。

    保存并替换：调试器将这个原始指令保存下来，然后用一条特殊的、会触发调试异常的指令（如 ARM 的 BKPT，或非法指令）覆盖写入该内存地址。

    运行与触发：CPU 执行到这条特殊指令时，就会触发调试异常，从而进入调试状态。

    恢复：调试器需要恢复执行时，会用保存的原始指令换回 BKPT 指令，并让 CPU 继续运行。

3、CPU停了，JTAG 为什么还能继续工作
    JTAG接口与CPU的时钟是独立的或者说是可以异步的

    JTAG 的TAP 控制器有自己的时钟 TCK ，它不依赖 CPU的HCLK ，即使 CPU 核心因为调试暂停而停止了 HCLK ，只要调试器还在提供 TCK ，TAP 控制器就能正常工作，继续接受 调试器的命令
