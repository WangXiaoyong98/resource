1、内存屏障指令 
    在这条指令之前的内存操作必须在这条指令之后的内存操作开始之前全部完成，并且对系统中的其他观察者（如其他 CPU 核心、DMA控制器）可见

    1.1 为什么需要内存屏障
        现代高性能处理器为了提升执行效率，会采用两种可能导致指令 乱序 的优化手段
        
        1.1.1 编译器优化 
        1.1.2 CPU乱序执行 ： CPU 为了填满流水线，会动态调整指令的执行顺序，只要不破坏单线程的逻辑自洽性

        此外，还有写缓冲（store buffer） 和 缓存（cache）的存在： CPU 执行写操作后，数据可能只是存在写缓冲或者 L1 缓存中，并没有到主存或系统总线，对于其他 CPU 核心来，这个数据还是不可见的状态

    1.2 ARM架构中的三大屏障指令

        DMB（Data Memory Barrier） 数据内存屏障： 确保屏障前的所有数据内存访问（读写），在屏障后的任何数据内存访问开始之前，对系统中的所有其他观察者可见
        DSB (Data Synchronization Barrier) 数据同步屏障： 在DMB 的基础上，会停顿 CPU 的执行，直到屏障前的所有数据内存访问真正完成（数据已离开写缓冲、缓存已刷新）
        ISB （Instruction Synchronization barrier）指令同步屏障： 刷新CPU的流水线，强制重新从缓存或者内存中获取所有指令，通常和 DSB 配合使用，用于确保内存操作对指令获取的影响立即可见

        DMB： 只保证顺序，不等待
        DSB： 保证顺序，并完成的等待
        ISB： 清空流水线操作
