9. What is IP verification and what is its main goal?
    IP verification is the process of checking whether hardware IP block, like UART or I2C, works correctly according to its reference menu. The main goal is to find design bugs before the chip is manufactured. This helps save time and money, because fixing a bug after tape-out is very expensive.
    中文对照：
    IP验证是检查某个硬件IP模块（如UART或I2C）是否按照规格书正确工作的过程。主要目标是在芯片流片前发现设计bug，因为流片后再修bug非常昂贵。

10. What's the difference between verification and testing?
        Answer:
        Verification is done before the chip is fabricated, using simulation tools. Testing is done after the chip comes back from the factory, on real hardware. 
        Verification finds design bugs; testing finds manufacturing or physical defects.

        中文对照：
        验证在流片前进行，使用仿真工具。测试在芯片流片后进行，在真实硬件上运行。验证发现设计bug，测试发现制造或物理缺陷。

11. Can you walk me through a typical IP verification flow?
    Answer:
    Sure. First, I read the IP specification and make a verification plan. Then I build the verification environment. Next, I write test cases, run simulations, and debug any failures. After that, I collect coverage and run regression tests. Finally, when all tests pass and coverage goals are met, I sign off.

    中文对照：
    当然。首先阅读IP规格，制定验证计划。然后搭建验证环境，通常包括driver、monitor和scoreboard。接着写测试用例，跑仿真，调试问题。之后收集覆盖率，跑回归测试。最后，当所有测试通过且覆盖率达到目标时，做签收。

12. If a simulation fails, what are your debugging steps?
    Answer:
    First, I check the simulation log to find when the failure happened. Then I open the waveform and check the interface signals. Next, I trace back to see if the test case itself is wrong. After that, I check if the reference menu is correct. Finally, I locate the issue to a specific RTL module and discuss it with the design engineer if needed.

    中文对照：
    首先检查仿真日志，定位失败时间点。然后打开波形，检查接口信号。接着回溯，看是否测试用例本身写错了。之后检查参考模型是否正确。最后把问题缩小到具体的RTL模块，必要时和设计工程师讨论。
